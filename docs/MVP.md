# 📋 MVP — Minimum Viable Product

> Автор: Алекс (@Alexwp01) · Задача #4  
> Версия: 1.0

## Что такое MVP

Минимально рабочая версия проекта, которую показываем Виктору на презентации.  
Не идеальная — но полный цикл работает без вмешательства разработчиков.

## Полный цикл

| Шаг | Действие |
|-----|----------|
| 1 | Пользователь регистрируется и входит |
| 2 | Загружает документ (PDF / DOCX / TXT) |
| 3 | Оплачивает через Stripe (test mode) |
| 4 | Документ переводится через Ollama |
| 5 | Нотариус получает email и подписывает |
| 6 | Пользователь видит статус `done` и скачивает |
| 7 | Всё крутится в Kubernetes (k3s на VDS) |

## ✅ Входит в MVP

- Регистрация/логин (email + пароль, JWT)
- Загрузка файлов PDF/DOCX/TXT в MinIO
- Оплата через Stripe Checkout + webhook
- Перевод через Ollama (очередь Redis/BullMQ)
- Email нотариусу + кабинет нотариуса + подпись
- Кабинет пользователя со статусами документов
- Docker Compose (локально) + k3s + Cloudflare Tunnel

## ❌ Не входит в MVP

- OAuth, 2FA
- Выбор языка перевода пользователем
- Подписки, возвраты, production Stripe
- Цифровая подпись PKI/eIDAS
- Мониторинг (Grafana/Prometheus)
- HorizontalPodAutoscaler, KEDA
- Playwright e2e тесты
- Нагрузочное тестирование

## Definition of Done

Задача закрыта когда:
- [ ] Код смерджен в `main` через Pull Request
- [ ] Работает в `docker-compose` локально
- [ ] End-to-end flow (#17) проходит
- [ ] Нет блокирующих ошибок в логах

## Правила изменения scope

1. Открой issue с лейблом `scope-change`
2. Согласие минимум 3 участников в комментарии
3. Реализуемо за ≤ 1 день одним человеком
4. Алекс (@Alexwp01) обновляет версию документа
